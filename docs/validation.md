# 验证范围

## 仓库检查

默认检查针对技能发行与来源完整性，包含确定性生成、原始 frontmatter、文件内容和模式、路径安全、篡改检测、失败保护及标准安装目录。这些检查不调用 OMA，不证明目标部署已经实现所有 CMA 功能。

`scripts/upstream.py check --online` 从官方固定提交重新构建预期内容，避免仅凭本地摘要自证正确。

## 安装与 metadata 兼容

标准 `skills` 安装器已在隔离目录中以 Codex 项目级 copy 模式安装此发行版；只发现一个 `claude-api`，全部发行文件一并安装。

本次安装器版本为 `skills 1.8.1`。安装后的 97 个文件与发行目录逐字节一致。

当前官方 description 为 1068 字符，通用 `skill-creator/quick_validate.py` 的 1024 字符限制会同时拒绝官方原文件和本发行版。本项目保留官方 metadata，没有为通过该通用校验器而截断描述。需要严格执行这一长度上限的宿主仍有兼容限制；安装器成功不代表所有宿主都已验证。

## 行为检查

验证技能行为时，在干净项目副本中安装完整 `skills/claude-api/`，使用官方子命令和 SDK。区分：

- 技能能否选择并遵循官方流程。
- 生成的代码是否满足项目合同。
- 目标 OMA 实例是否真正执行了请求。

工具需要调用及结果回传证据；持久化需要读取存储后的证据；文件交付需要实际下载与内容检查。未执行、缺少依赖或被上游步骤阻断的项目不能标为通过。默认 CI 不创建远端资源或消耗模型额度。

本发行版另完成三次独立上下文的只读规划检查：

- 明确的 OMA 请求面对原有 OpenAI Python 代码时，保持 OMA 目标并选择官方 SDK。
- 明确要求 OMA 托管多轮 Agent 时，沿用官方 onboarding、Session 和 custom-tool 事件，不改为单次模型代理。
- Anthropic 官方平台请求继续使用官方流程，未被 OMA 部署说明重定向。

这三次都通过显式调用加载技能，没有在规划阶段索取凭证或创建资源。它们验证路由和作用范围，不证明宿主自动发现，也不替代真实后端执行验证。

## 已有观察的使用范围

2026-11-15 的前期独立场景试跑使用旧版 OMA 入口和另一份上游快照，因此不作为本发行版的端到端通过证明。那些试跑验证了普通多轮对话和重复部署，也遇到工具调用、远端工具服务、Outcome 启动及计价配置方面的部署问题。

这些记录不进入技能运行指令，不携带私有域名、凭证、资源 ID 或客户数据，也不声明所有 OMA 实例有相同限制。目标部署的能力仍按官方流程实测。需要修复的后端故障不通过改写技能描述掩盖。
